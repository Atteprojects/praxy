# API reference

Praxy's HTTP API is documented via an OpenAPI 3.1 document generated by .NET 10's built-in document
generation (architecture.md §8) — never hand-maintained, so it can't drift from the actual routes.

## For local development

Run the API in the `Development` environment (`dotnet run --project src/Praxy.Api` with no
`ASPNETCORE_ENVIRONMENT` override does this by default) and open **`/scalar/v1`** — a full
interactive UI: every endpoint, request/response schemas, and a "Try it" panel that fires real
requests against your running instance. The raw document is at `/openapi/v1.json`.

Both are **deliberately unavailable outside Development** (`Program.cs` gates them behind
`app.Environment.IsDevelopment()`) — they disclose the full API surface including every internal
console-admin route, which a production instance shouldn't advertise to anyone who reaches it.

## For a released version

[`docs/openapi/v1.json`](openapi/v1.json) is the generated document for this release, committed so
it's available without running an instance — "published per release," not regenerated ad hoc.
Open it with any OpenAPI-compatible viewer:

- **Fully offline, zero install:** any editor with an OpenAPI extension, or drag the file into
  [Swagger Editor](https://editor.swagger.io) / [Redocly](https://redocly.com/redoc) running locally.
- **One command, needs Node** (already a Praxy console dev dependency, nothing new to install):
  ```bash
  npx @scalar/cli document serve docs/openapi/v1.json
  ```
- **The real interactive UI:** run the instance locally in Development and use `/scalar/v1` (above)
  — the only option that can actually fire "Try it" requests, since a static file has nothing to
  call.

## Regenerating for a new release

```bash
ASPNETCORE_ENVIRONMENT=Development dotnet run --project src/Praxy.Api &
curl -sS http://localhost:5090/openapi/v1.json -o docs/openapi/v1.json
```

Commit the updated file as part of the release. It's plain generated JSON — diffs are meaningful
(a route added/removed/reshaped shows up directly) and easy to review before tagging.
